# Источники истории версий Steam — краткий разбор

Сводка по подборке ChatGPT + что из этого проверено руками 17.11.2026.
Задача: дать плагину список старых версий игры (buildid + manifest GID по депо),
не нарушая правила Steam и не обходя права аккаунта.

## 1. Главное в одном абзаце

Единственный источник, который **уже проверен и работает** — SteamRaw: публичный
JSON API без ключа, история с сентября 2026, отдаёт buildid по веткам и изменения
`depots.<depot>.manifests.<branch>.gid` (old → new), причём GID приходят строками,
то есть без потери точности. Из этого восстанавливается снимок манифестов на момент
сборки. Глубокая история есть только у SteamDB, но у неё нет API и запрещён
автопарсинг — значит только ручной ввод. Всё остальное из подборки — либо
непроверенные сторонние сервисы, либо базы ключей депо (обход прав, не использовать).

## 3. Что именно проверено на живой системе

- `GET https://steamraw.com/api/app/1091500` → 200, JSON (имя, издатель, цена).
- `GET .../builds` → 200, список `{buildid, branch, time_updated}`; у Cyberpunk 2077
  5 сборок public с 22–23 октября 2026, у OBS Studio — 18 веток, у TF2 — 8 public.
- `GET .../history` → 200, 261 запись; есть ключи
  `depots.1091501.manifests.public.gid`, `old_value`/`new_value` **строками**
  (`"2461377369266892508"`), то есть 64-битные GID не портятся.
- `GET https://api.steamcmd.net/v1/info/1091500` → 200, текущие 24 депо public.
- Реконструкция «текущие манифесты → откат по истории → снимок на момент buildid»
  реализована и проверена на реальных данных: для всех сборок Cyberpunk получается
  24 депо, снимок свежей сборки совпадает с текущим AppInfo.
- `https://steamcounts.info/app/1091500` → 200, HTML. Разобрано: таблица Updates
  (дата наблюдения, ветка, build «старый → новый», число изменённых депо, changelist)
  и таблица Depots (depot, размер, ОС, manifest GID). На живой странице Cyberpunk
  парсер выдаёт 24 депо с GID и 5 обновлений — см. `backend/lib/steamcounts.lua`.
  Публичного API нет, страница разбирается как есть.
- Проверено пробой ещё 17.11.2026 (`node tools/probe-sources.mjs`): SteamDB отдаёт
  HTTP 403 (и автопарсинг запрещён), HubcapDB отдаёт HTML-заглушку (нужен Discord-логин
  и личный ключ), SMD отдаёт только свой веб-интерфейс, а домены `opensteamdb.net`,
  `steamappdb.net`, `manifest-api.ryuu.space` не отвечают.

## 4. Чего в подборке не хватает / что неверно

1. **История SteamRaw начинается в сентябре 2026.** Всё, что старше, восстановить
   нельзя: у таких сборок снимок манифестов будет неполным. В подборке это
   упомянуто, но вывод «заменит SteamDB» — нет, не заменит.
2. **Одна сборка ≠ один манифест.** Версия игры — это набор депо: контент, exe,
   языки, DLC, платформенные файлы. Любой источник, который отдаёт «один GID на
   версию», для отката непригоден.
3. **ManifestHub — это не история версий, а ключи депо.** Использование таких
   ключей = доступ к контенту, который аккаунту не разрешён. В публичный плагин
   это тащить нельзя ни в каком виде.
4. **opensteamdb-api / HubcapDB / Ryuu** — не проверены; у Hubcap и Ryuu нужен
   личный ключ пользователя, значит это не «бесплатный источник», а интеграция
   с авторизацией и лимитами.
5. **Идея «своя база, которую пополняют пользователи»** технически верная, но
   требует: согласия, сервера, модерации и защиты от мусора. Это отдельный проект,
   а не галочка в плагине.
6. **Локальные данные пользователя** (`appinfo.vdf`, `content_log.txt`,
   `depotcache/*.manifest`) — самый недооценённый пункт: там может быть история
   конкретной машины, которой нет ни у кого. Но формат `appinfo.vdf` меняется
   между версиями клиента, а `content_log.txt` пишется не всегда.

## 5. Рекомендованный порядок работ

Статус на 17.11.2026 (после передачи задачи):

1. **SteamRaw** — ✅ сделано: кнопка «Загрузить историю» → buildid → подстановка
   манифестов в план, с пометкой «сборка старше истории».
2. **Локальный кэш** — ✅ сделано: модуль `backend/lib/localcache.lua` читает
   `logs/content_log.txt`, `steamapps/depotcache/*.manifest` и `appmanifest_*.acf`;
   RPC `get_local_cache`, кнопка «Проверить локальный кэш». Сборки SteamRaw,
   чьи манифесты есть в локальном кэше, помечаются «была на этом ПК»; любой
   найденный GID отправляется в план одной кнопкой.
3. **Ручной импорт SteamDB** — ✅ сделано: RPC `import_manifests` разбирает
   вставленный текст (`depotid gid`, `depotid, gid`, `DepotID … ManifestID …`)
   и подставляет пары в план. Сайт SteamDB не парсится.
4. **Своя база** — ✅ в базовом виде сделано: общая база `resources/versions-db.json`
   едет в `.star` и пересобирается скриптом `npm run db` (`tools/build-versions-db.mjs`)
   из SteamRaw + steamcmd.net; локальная копия — `%LOCALAPPDATA%\VersionRollback\versions-db.json`.
   Автозагрузки на сервер нет: найденное локально сохраняется в локальную базу и
   выгружается отчётом в JSON, который пользователь отправляет вручную.
   Полноценный сервер с модерацией — отдельный проект, если появится спрос.
5. Hubcap/Ryuu — опционально, с ключом пользователя, если появится спрос.

## 6. Границы, которые лучше не переходить

- Никаких ключей депо и «фиксов лицензии»: скачивание только через Steam и только
  для того, что есть на аккаунте.
- Никакого автопарсинга SteamDB: у них это прямо запрещено, а плагин с автообновлением
  быстро получит блокировку.
- Никаких торрентов и сторонних зеркал игровых файлов.

## 7. Состояние проекта (для передачи)

- Репозиторий: https://github.com/Stintik-123/steam-version-rollback (публичный, MIT).
- Релиз: https://github.com/Stintik-123/steam-version-rollback/releases/tag/v0.1.0.
- Бэкенд собирается в один файл `tools/bundle-backend.mjs` — в упакованном `.star`
  `require` соседних Lua-файлов не работает.
- SteamRaw-модуль: `backend/lib/steamraw.lua` (`builds`, `history`, `reconstruct`),
  RPC `get_versions`, UI-блок «История версий» в `frontend/ui/VersionPanel.tsx`.
- Локальный кэш: `backend/lib/localcache.lua` (`parse_content_log`,
  `parse_depotcache_name`, `parse_manifest_text`, `scan`, `group`, `report`),
  RPC `get_local_cache` и `import_manifests`, UI-блоки «Локальный кэш Steam» и
  «Импорт из SteamDB».
- SteamCounts: `backend/lib/steamcounts.lua` (`parse_depots`, `parse_updates`,
  `fetch`, `collect`), RPC `get_steamcounts` и `add_steamcounts_db`, UI-блок
  «Источники данных» с полным списком подборки и живой проверкой доступности
  (RPC `probe_sources`). Скрипт проверки: `node tools/probe-sources.mjs`.
- База версий: `backend/lib/versiondb.lua` (общая база из ресурса + локальная
  копия, слияние, `has_manifest`, `add_build`), RPC `get_db_summary`,
  `get_versions` (теперь отдаёт сборки SteamRaw **и** базы), `collect_local`,
  `save_local_db`, `export_local`. Сборщик: `tools/build-versions-db.mjs`
  (`npm run db`), список игр — `tools/versions-db-apps.json`, результат —
  `resources/versions-db.json` (ездет в `.star` как ресурс).
- Локальный сбор: тумблер «Локальный сбор данных» и карточка крупного обновления.
  Карточка с выбором «Да, собирать / Нет, не собирать» показывается **в разделе
  «Библиотека»** (баннер в правом нижнем углу, `frontend/ui/ConsentBanner.tsx` +
  `frontend/inject.tsx`), а не в настройках плагина. Бэкенд проверяет согласие

  токену, RPC `get_collection_report` / `post_github_issue`).
