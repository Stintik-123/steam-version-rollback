# Version Rollback

Плагин Millennium для Steam: поставить конкретную версию игры вместо текущей.

Вы выбираете ветку (включая legacy-ветки разработчика) или вбиваете manifest GID
вручную — Steam сам скачивает нужные депо через свою же команду `download_depot`,
после чего плагин может подменить файлы игры, сделав бэкап старой версии.

Ничего не скачивается в обход Steam и вашего аккаунта: доступны только те депо,
на которые у вас есть лицензия.

## Что уже работает

| Слой | Состояние |
| --- | --- |
| Lua-бэкенд: парсинг VDF/ACF, план загрузки, очередь депо, бэкап и подмена файлов | написан, покрыт тестами (53 проверки) |
| Фронтенд: панель в настройках Millennium | написан, `tsc --noEmit` без ошибок |
| Сборка `.star` | собирается (`starlight pack`) |
| Секция в свойствах игры («Версии и бета-версии») | код готов: DOM-инъекция в штатную страницу, живая проверка ещё не сделана |
| Хуки-патчи JS (`backend/patches.lua`) | каркас готов, якоря не подобраны — не используются, см. `docs/HOOKING.md` |
| Живой запуск бэкенда в Steam | проверен: сборка загружается, `millennium.ready()` вызывается, UI не падает |

## Установка

Минимально нужен Millennium 3.x со starlight (проверялось на 3.6.3) и Node.js для сборки.

```powershell
cd version-rollback
npm install
npm run pack          # соберёт build/com.versionrollback.steam.star
```

Дальше либо скопировать `.star` в `C:\Program Files (x86)\Steam\millennium\plugins\`
(потребуется повышение прав), либо собрать сразу в установленный Millennium:

```powershell
npm run build         # output_path = "auto" в millennium.toml
```

После установки — перезапуск Steam, затем **Настройки → Millennium → Version Rollback**.

## Где это в Steam

Основное место — там же, где Steam сам показывает версии:

**Библиотека → правый клик по игре → Свойства → «Версии и бета-версии»**.

Внизу страницы появляется блок **Version Rollback** с тем же выбором версии и кнопкой
загрузки. AppID подставляется из открытой игры автоматически (если не получилось —
выберите игру в списке внутри блока).

Резервный вход — **Настройки → Millennium → Version Rollback**: та же панель целиком,
если вставка в свойства не сработала (например, Steam поменял вёрстку или язык
интерфейса не входит в список распознаваемых).

## Как пользоваться

1. Выберите игру из списка установленных (или введите AppID).
2. «Подтянуть» — плагин возьмёт депо и манифесты из `api.steamcmd.net` (кэш 6 часов).
3. Выберите ветку. Если нужной версии в ветках нет — включите «Свой manifest ID»
   и добавьте пары `depotid → GID` (SteamDB → Depots → Manifests).
4. Режим:
   - **Только скачать** — файлы лягут в `steamapps/content/app_<id>/depot_<id>`,
     игру никто не трогает. Безопасный вариант, чтобы сначала посмотреть.
   - **Скачать и подменить** — после успешной загрузки всех депо ставит файлы на
     место игры, предварительно переименовав текущую папку в бэкап.
5. «Скачать эту версию» → прогресс по депо → «Применить подмену файлов».
6. «Вернуть как было» — возвращает папку из бэкапа.

Игра **не обязана быть установлена**: `download_depot` работает по лицензии, а не по наличию файлов. Без `appmanifest` плагин сам выбирает библиотеку с максимумом свободного места и качает только в `steamapps/content` (режим подмены при этом недоступен).

Для игр без публичных веток (как CoD на вашем скриншоте) есть путь через manifest ID:
кнопка **SteamDB: депо** открывает нужную страницу, оттуда берётся `depotid` и `Manifest GID`.

## Ограничения, о которых лучше знать заранее

- **Старые манифесты может быть недоступны.** Valve отдаёт только те манифесты,
  которые разработчик оставил доступными; на закрытые ветки и снятые билды
  `download_depot` вернёт ошибку. Это ограничение Steam, а не плагина.
- **Прогресс приблизительный.** Steam не отдаёт прогресс `download_depot` наружу,
  поэтому плагин считает размер файлов на диске. Отметка «готово» — эвристика
  (99.5% ожидаемого размера или 25 секунд без прироста); есть кнопка «готово вручную».
- **Steam захочет обновиться обратно.** После подмены не запускайте обновление
  игры. Кнопка «Задержка автообновления» пробует `app_delay_update` — это
  экспериментальная команда клиента, поведение зависит от версии.
- **Сетевые игры и античит** могут не пустить на старую версию. Это не лечится.
- **Место на диске.** Подмена не копирует файлы (переименование в пределах тома),
  но бэкап старой версии остаётся на диске, пока вы его не удалите.

## Разработка

```powershell
npm run dev           # starlight watch: перезапуск бэкенда и UI при правках
npm test              # Lua-тесты под fengari (Lua 5.3 в JS)
npx tsc -p tsconfig.json --noEmit
npm run pack          # сборка .star в build/
```

Почему тесты на fengari, а не на `millennium.luavm64.exe`: последний — IPC-хост,
он ждёт подключения от Millennium и произвольные скрипты не исполняет. Тесты
подменяют `fs`/`utils`/`logger`/`json` заглушками, поэтому не трогают диск и сеть.

### Структура

```
backend/main.lua        точка входа, on_load/on_frontend_loaded/on_unload, патчи
backend/rpc.lua         RPC-поверхность для фронтенда (JSON-строки, pcall)
backend/patches.lua     хуки в UI Steam (по умолчанию отключены)
backend/lib/vdf.lua     парсер Valve KeyValues (VDF/ACF)
backend/lib/steam.lua   библиотеки Steam, appmanifest, папки депо
backend/lib/appinfo.lua api.steamcmd.net: депо, ветки, манифесты, кэш
backend/lib/plan.lua    чистая логика выбора депо и манифестов
backend/lib/jobs.lua    очередь download_depot + измерение прогресса
backend/lib/swap.lua    бэкап, перенос файлов, откат
backend/lib/util.lua    пути, лог, JSON, форматирование
frontend/index.tsx      definePlugin + FFI-функция execConsole
frontend/ui/VersionPanel.tsx  панель
frontend/lib/rpc.ts     обёртки над backend.*
resources/labels.json   подписи веток (можно переопределить своим файлом)
tests/                  Lua-тесты и фикстуры ACF/VDF
tools/probe.js          диагностика клиента в DevTools
docs/HOOKING.md         как подбирать хуки
```

Свой `labels.json` кладётся в `%LOCALAPPDATA%\VersionRollback\labels.json` и
важнее встроенного: `{ "1091500": { "2_31_old": "2.31 — до Phantom Liberty" } }`.
